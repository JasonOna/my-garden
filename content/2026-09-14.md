To illustrate Tom Wheeler's presentation, here is how the e-commerce checkout workflow evolves from a naive approach into a complex distributed mess (pre-Temporal), and how Temporal restores it to clean, resilient code.

## 1. The Naive "Happy Path" (Pre-Temporal)

Initially, a developer writes straightforward, synchronous code. It assumes everything works perfectly, the network never drops, and APIs respond instantly.

``` python
# 🚨 DANGER: This will fail catastrophically in production if any step drops.
def checkout_process(order_id, user_id, amount):
    payment_gateway.charge(user_id, amount)
    inventory_service.reserve_items(order_id)
    shipping_service.create_shipment(order_id)
    email_service.send_confirmation(user_id)
```

## 2. The Distributed Reality: Async & Idempotency (Pre-Temporal)

In a real microservices architecture, any network call can time out. If payment_gateway.charge times out, did the bank charge the user?
To prevent charging the user twice, the code must become asynchronous (queues, retries) and idempotent (tracking unique IDs). The business logic quickly gets buried under infrastructure plumbing:

``` python
import uuid
# 🤯 COMPLEX: Half the code is just managing state, timeouts, and idempotency
def checkout_process_distributed(order_id, user_id, amount):
    # 1. Generate an Idempotency Key to prevent double-charging
    idempotency_key = str(uuid.uuid4())
    
    # 2. Asynchronous Retry Loop for Payment
    while True:
        try:
            payment_status = payment_gateway.charge(user_id, amount, idempotency_key)
            if payment_status == "SUCCESS":
                break
        except TimeoutError:
            # Did it succeed? We don't know. We rely on the idempotency_key 
            # to safely retry without double-charging.
            log.warning("Payment timed out. Retrying safely...")
            time.sleep(5) 
        except PermanentFailure:
            # 3. Saga Pattern / Compensating Transaction
            inventory_service.release_items(order_id)
            raise Exception("Checkout failed")

    # 4. State persistence is required here before moving to the next microservice...
    # (Imagine duplicating this massive try/except loop for Shipping, Inventory, etc.)
```

## 3. The Temporal Solution (Post-Temporal)

Temporal introduces durable execution. It allows you to write the clean, straight-line code from the first example, but automatically handles the timeouts, retries, and state tracking under the hood.
If the server crashes mid-execution, Temporal resumes exactly where it left off, ensuring each step executes exactly once.

``` python
from datetime import timedelta
from temporalio import workflow

# We define the steps as standard activities with retry policies
@workflow.defnclass CheckoutWorkflow:
    @workflow.run
    async def run(self, order_id: str, user_id: str, amount: float):
        
        # Temporal automatically guarantees idempotency and handles retries automatically
        await workflow.execute_activity(
            charge_payment, 
            args=[user_id, amount], 
            start_to_close_timeout=timedelta(seconds=10)
        )
        
        await workflow.execute_activity(
            reserve_inventory, 
            args=[order_id], 
            start_to_close_timeout=timedelta(seconds=5)
        )
        
        await workflow.execute_activity(
            create_shipment, 
            args=[order_id], 
            start_to_close_timeout=timedelta(seconds=5)
        )
```
